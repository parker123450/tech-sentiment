# 科技情绪全景 · 第六轮计划（草案，等你确认）：每天自动扫一遍、一眼看懂

写于 2026-10-22 深夜。你的要求：**每天自动扫市场情绪**（成交、期权、速度和加速度这些客观的东西，不靠主观），**可视化**，并且想看看"怎么重新构造一个最好的版本"。下面先说读完五轮之后的判断，再给方案。

## 一、读完五轮之后的判断

### 站得住、该留的

| 东西 | 为什么留 |
|---|---|
| 数据管线（Yahoo、FRED、CBOE，单品种兜底，先写临时文件） | 10-21 的事故修过以后是稳的，云端也能跑通 |
| `engine.py` 的"先登记再检验、结果只决定标签"（`SPEC` / `COMBOS` / `MEASURE`）、`--selftest` | 这是整个项目防止"贴着历史调分数"的骨架，重写只会把它弄丢 |
| 共通口径（涨跌按自己的波动折算、成交量除以均量、和全部历史比） | 让同一条规则对半导体、英伟达、KOSPI 都适用 |
| 两个真正能衡量的：期权隐含波动 → 之后一个月的幅度；200 日线下方 → 下跌风险 | 33 个品种、两段历史都成立，不依赖我们自己定的刻度 |
| 情绪分 + 三个温度 + 对照格 + 清单 + 退潮确认 | 你定下的描述框架；审查说明"定价恐慌"是里面最独立的部分（价格只能解释三分之一） |
| 样本外日志 `daily_log.csv` | 唯一干净的检验，刚开始攒 |

### 问题（按重要性）

1. **云端定时任务今天一次都没自动跑。** 工作流是 UTC 11:31 建的，之后 13:05 到 15:35 的 6 个定时点一个都没触发，Actions 里只有 4 次手动运行；网站停在 10-21 收盘，今天盘中没有更新。可能是 GitHub 对新建仓库的定时有延迟，也可能是整点、半点附近拥堵（GitHub 自己也说定时常晚、偶尔跳过）。不管哪种，"每天自动扫"现在还不成立，而且**没有东西会告诉你它没跑**。
2. **页面是五轮叠出来的，"扫一遍"的功能散在各处。** 情绪分、合理区间、超出价格的恐慌、三个温度、对照格、5+6 条清单、退潮确认、六层读数、三件事、每日一览、期权五问、历次对照……每轮加、很少减。想知道"今天各项指标在哪、哪些变了"，得翻好几块。
3. **"变化"这个维度弱。** 你说的"加速度"现在只有情绪分的 10 天速度（急冷 / 急升）和价格的 10 天加速度。VIX 几天内涨了多少、认沽/认购比在抬还是在落、成交在放还是在缩、广度在修复还是恶化，这些"方向盘"没有系统地扫。
4. **半导体自己的恐惧只有 3 天历史。** SMH 等的隐含波动从 10-19 才开始攒，之前只能拿纳指 VXN 折算。免费数据里没有更好的来源；要长历史只有盈透（你说先不做）。
5. **推送和"每天扫"不匹配。** 现在只推强信号，平时一条也没有；手机 ntfy 你还没装。
6. 小问题：云端 `daily_log.csv` 最早三天的 `score` 列是空的（列是后加的，没回填）；本机还挂着两个旧的预览服务器进程；内置浏览器打不开 localhost（权限）。

### 关于"重新构造"

- 真正限制"衡量得准不准"的不是代码，是**数据和样本**：半导体没有自己的长期期权历史，大跌只有 15 次。推倒重写代码不会改变这一点。
- 引擎和管线是好的，**页面和自动化是弱的**。所以我建议：**保留引擎和数据管线，围绕"每日扫描"重做输出层，把自动化做到可信**，而不是推倒重来。

## 二、两条路

| | A. 保留引擎，重做输出层和自动化（**推荐**） | B. 推倒重来（新数据库、模块化引擎、前端框架） |
|---|---|---|
| 衡量质量 | 不变（受限于数据） | 不变 |
| 风险 | 低：`--selftest` 和研究结论都在 | 高：五轮验证过的逻辑要重写一遍，容易出错 |
| 工作量 | 中，一轮能做完 | 大，而且先退步再追平 |
| 你能看到什么 | 每天一张扫描表 + 一条推送 | 短期什么都看不到 |

## 三、方案 A 要做的事

### 1. 自动化做到可信（先做，不然后面都白搭）

- 定时改到不拥堵的分钟（例如每小时 17、47 分），仍然每 30 分钟一次。
- **看门狗**：收盘后最后一次运行检查"网站的数据日期 = 最近一个交易日"，不是就推一条"今天没更新"到手机；页面顶部数据过期超过一个交易日时显示醒目的警告条。
- 回填 `daily_log.csv` 的 `score` 列（全量计算，`--selftest` 保证和当时一致）。
- 明天先观察定时是否开始触发；如果 GitHub 的定时一直不可靠，备选是用一个免费的外部定时器调用工作流（要你建一个只能触发工作流的令牌，到时再问你）。

### 2. "今日扫描"：新的第一屏（核心）

每天一张表，**行是指标，列是今天、昨天、5 天前、历史分位、5 日变化在自己历史里的分位（就是"加速度"）、灯**。灯按已经登记的恐慌 / 过热刻度，不新造刻度。颜色只标极端，不花哨。

| 组 | 指标（都已经在引擎里，只是没有集中扫） |
|---|---|
| 期权定价 | VIX、VIX÷50 日均、VIX÷VIX3M、VIX9D÷VIX、VXN、VVIX、SKEW、SMH 30 天隐含波动、SMH 期限结构、SMH 偏度、隐含÷实际 |
| 成交与仓位 | 股票认沽/认购比 10 日均、指数认沽/认购比、SOXL÷SOXS 成交额、SMH 相对成交量、20 日涨跌日量比、SMH 期权认沽/认购成交比、持仓变化 |
| 价格与速度 | 回撤（按波动折算）、离 200 日线、20 日 Z 分数、10 日加速度、RSI、当天涨跌折合几倍日波动、21 天实际波动 |
| 参与度与跨市场 | 成分股在 50 / 200 日线上方的比例、新高减新低、等权÷市值、KOSPI 回撤和速度、海力士、三星、Baa 20 日、HYG÷IEF |

表上面自动写三到五条要点："今天变了什么"：哪些灯新亮、哪些熄灭，哪些指标 5 日变化进了自己历史最快的 5%。这就是"自动扫"。

情绪分、三件事、对照格仍在，但放到扫描表下面；它们回答"在哪一段"，扫描表回答"今天动了什么"。

### 3. 每天一条推送（收盘后）

ntfy 一条，三四百字：情绪分和档位、比昨天变了多少、三个温度、今天新亮 / 熄灭的指标、期权给的下个月预期范围、下跌风险档、一句话结论。盘中强信号推送照旧。手机装 ntfy 订阅频道这件事还是要你做。

### 4. "变化率"登记进规则表

在 `engine.py` 新开一组 `delta`（只作描述，不进任何判断）：每个指标 5 日变化在自己全部历史里的分位，只用当天以前。刻度是整数惯例（最快 5% 算"急"）。不做方向预测，也不进情绪分。

### 5. 页面收敛（折叠，不删）

顺序改成：今日扫描 → 情绪分和三件事 → 对照格和清单 → 每日一览 → K 线 → 期权 → 参与度 → 历次对照（默认折叠）→ 说明。六层读数并进扫描表；合理区间、超出价格的恐慌保留，但收成一行加 i 提示。所有你定过的公式、分档、刻度不动。

### 6. 可选的新数据（你挑，不挑就不做）

| 数据 | 衡量什么 | 来源 / 频率 | 说明 |
|---|---|---|---|
| 事件日历：英伟达、台积电、三星、海力士、美光财报；FOMC、CPI；期权到期日 | "担心的是眼前还是以后"有了参照 | 财报日从 Yahoo 取，FOMC、CPI 用公布的年度日程，到期日算出来 | 第五轮待办第 11 条 |
| 跨资产：美元兑日元、10 年期美债、美元兑韩元、比特币 | 风险偏好的确认 | Yahoo，日线 | 只描述 |
| NAAIM 主动经理仓位、FINRA 融资余额、做空余额 | 人群行为（仓位），不是问卷 | 周 / 半月 / 月，免费 | 频率低，只能看趋势 |
| 盈透 SMH、SOXX、英伟达历史隐含波动 | 半导体自己的恐惧 | 需要你装 TWS、只读 API | 你说过先不做 |

## 四、不做什么

- 不训练模型，不改任何已登记的阈值、公式、分档。
- 不把"变化率"做成信号或进情绪分。
- 不重写引擎和数据管线。
- 不碰账号、不下单。
